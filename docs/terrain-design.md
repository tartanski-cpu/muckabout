# Terrain engine design (M1)

Short version: everything at rest is a layered heightfield owned by a worker; main keeps a read-only
mirror for queries and rendering; material only becomes particles (clods) while airborne.

## Data layout (`src/terrain/core.js`, no DOM/three dependency)

World = `nx × nz` height samples on a `cell` = 0.25 m lattice (480 × 480 for the 120 m map), grouped
into 32 × 32 chunks for dirty tracking and upload. Structure-of-arrays, index `c = j*nx + i`:

| Array | Type | Meaning |
|---|---|---|
| `bed` | Float32 | immovable bedrock height |
| `nl` | Uint8 | number of layers (0–3) |
| `lm`, `lt` | Uint8 / Float32, ×3 | layer material and thickness, stored bottom → top |
| `h` | Float32 | cached surface = bed + Σ thickness |
| `dist` | Uint8 | disturbed (0 = virgin, 255 = worked) for colour |
| `rut` | Float32 | compaction depth already applied by tyres/tracks |
| `wet` | Uint8 | 1 if under water (lower angle of repose) |

Adding a fourth layer merges the bottom two (volume conserved; the thinner one takes the thicker
one's material). Materials and their properties live in `materials.js`.

## Relaxation

A FIFO work list of dirty cells (ring buffer + `queued` flag, so each cell is in it at most once).
Processing a cell compares it with its 8 neighbours in both directions; where the slope exceeds the
top material's talus (wet or dry) a fraction of the excess top-layer material moves downhill and both
cells are re-queued. No sweeps: an untouched map costs nothing, and "awake chunks" is just the set
of chunks the work list touched this tick. A per-tick cell budget bounds worst-case time; leftover
work carries to the next tick.

## Commands and results

The sim is driven by one message per fixed 60 Hz step, so it is deterministic for a given command stream.

```
main → worker  {t:'init', map, seed}
               {t:'tick', n, cmds:[...]}        cmds: cut | deposit | compact | (M5) water params
               {t:'audit'} {t:'snapshot'}
worker → main  {t:'tick', n, results:[...], chunks:[{id, h:Float32Array, info:Uint8Array}], stats}
               {t:'audit', ...}
```

- `cut`: a tool floor rectangle given as previous and current world corners. The core sweeps it in
  sub-steps of half a cell (no tunnelling), removes everything above the floor, gives up to
  `capacity` m³ to the caller (per material) and windrows the rest ahead of the lip. Returns taken
  volumes and a resistance figure (Σ volume × dig resistance).
- `deposit`: clod landings, bilinear into 4 samples.
- `compact`: tyre/track footprints; soft materials rut, the lost volume is booked as `compacted`.

Chunk payloads are whole 32 × 32 blocks of `h` plus `info` (top material, disturbed, wet, layer count),
transferred, then written into the mirror and into two world-sized textures with one sub-image upload each.
`TerrainClient` hides whether the core runs in a worker or inline (`?worker=0`, tests, fast-forward).

## Containers and clods (main thread)

- `ContainerField`: a small heightfield in the container's own frame with per-edge wall heights. It
  relaxes against world-up expressed in that frame, so tilt makes material run to the low edge and
  over it; whatever leaves becomes clods at that edge. Bucket, dumper bed and hopper are the same class.
- `Clods`: SoA ballistic particles `{material, volume}`, budget 1,500. They sample the mirror and the
  containers; landing in a container adds to it, landing on ground queues a `deposit`.
- Every transfer between heightfields is a clod, except tool → own container on a cut.

## Rendering

- Ground: 5 × 5 tiles of 96 × 96 cells sharing two static grids (full and half resolution, with
  skirts). The vertex shader reads height with `texelFetch` from an R32F texture; the fragment shader
  derives flat normals from derivatives and colour from the info texture. No geometry rebuilds.
- Chips: three instanced meshes (gravel shards, mud clumps, grass tufts) filled from per-chunk lists
  generated by hashing cell + material, for chunks near the player; a chunk's list is rebuilt when it changes.
- Clods: one instanced mesh, per-instance tint by material.

## Budget plan (Quest 3, 13.9 ms)

| Item | Budget | How it is held |
|---|---|---|
| Worker tick | ≤ 6 ms | relax cell budget per tick; cut cost ∝ tool footprint |
| Main sim | ≤ 3 ms | clods O(n) with no clod–clod tests; containers ≤ 300 cells each |
| Upload | ≤ 0.5 ms | only dirty chunks; 4 KB + 4 KB per chunk |
| Draw calls / tris | ≤ 150 / 400k | 25 ground tiles max, LOD halves the far ones, 3 chip meshes, 1 clod mesh |

## Tests

`tests/terrain*.test.js` run the core directly: volume conservation (ground + containers + clods +
lost + compacted constant within 0.1 %) over scripted cut/dump sequences, repose angles per material,
swept cuts not tunnelling, determinism (same commands → identical arrays).
